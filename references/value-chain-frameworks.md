# 业务流程框架多源参考（Value Chain Frameworks Multi-Source Reference）

> **定位**：BA-L1 价值链识别与 L1-L3 标准骨架锚定时，MUST 本着"多框架交叉验证"原则参照本文件；价值链链属边界（主链/使能链/支撑链）判定 MUST 参照本文件 §7。
> 单一框架（仅华为 4A 或仅 TOGAF）不足以覆盖所有行业场景；不同框架各有所长，交叉参照可显著提升价值链命名的行业适配性与说服力。

## 1. 框架全景与选用原则

| 框架 | 定位 | 强项 | 适用场景 | 局限 |
|------|------|------|---------|------|
| **华为 4A 价值链实践** | 企业级端到端业务流（MTL/LTC/ITR/IPD 等） | 国内企业广泛认可，与 4A 架构体系原生契合 | 营销、销售、研发、售后类价值链 | 供应链/制造环节颗粒度不如 SCOR |
| **SCOR（供应链运营参考模型，ASCM）** | 供应链运营标准 | 计划-寻源-制造-交付-退货全流程标准化定义；双循环价值流；KPI 体系完备 | 供应链、制造、订单交付类价值链（如 OTD） | 不覆盖营销/研发前端 |
| **APQC PCF（流程分类框架）** | 跨行业通用流程分类字典 | 13 个顶级类别的通用流程编号体系，天然 5 级分层 | 全景规划、跨行业对标、L2/L3 节点编号参照 | 偏"清单式"，缺乏端到端编排视角 |
| **EBPM（企业业务流程管理方法论）** | 端到端流程 × 职能流程双维度建模 | 与本 skill"价值线/能力线"双维度天然同构 | 流程要素治理（角色/制度/风控/系统/数据） | 需结合行业框架落地 |
| **TOGAF / ArchiMate** | 企业架构国际标准 | 业务架构元模型、能力地图标准 | 全局架构语言统一 | 价值链模板需自行组装 |
| **行业实践（离散制造 OTD 等）** | 行业落地经验 | 贴近真实业务场景与行业术语 | 制造、外贸、重工配件等行业场景 | 非标准，需锚定到上述标准框架 |

**选用原则（ MUST 遵守）：**
1. **主框架先行**：先按业务场景选定主参考框架（见 §5 选择指南）
2. **交叉参照**：L1-L3 节点命名以主框架为准，用至少一个其他框架交叉验证覆盖度（无重大遗漏/无语义冲突）
3. **编号可溯源**：采用 APQC PCF 编号体系或 SCOR 流程编号为 L2/L3 节点附注参照编号，确保可溯源
4. **自定义必须挂靠**：自定义价值链/节点 MUST 附注参照框架及编号（Red Line #11）

## 2. SCOR（供应链运营参考模型）

SCOR（Supply Chain Operations Reference）由 ASCM（美国供应链管理协会）发布，是供应链领域事实上的国际标准。

### 2.1 双循环价值流

SCOR 将供应链视为**双循环价值流**结构：

```
┌────────────────────────────────────────────────────────────┐
│                     使能流程 Enable                          │
│        （绩效管理、人力资源、资产管理、信息技术等，纵向贯穿）      │
├────────────────────────────────────────────────────────────┤
│   【正向循环：订单履行主价值流】                                │
│                                                              │
│   Plan(计划) ──► Source(寻源) ──► Make(制造) ──► Deliver(交付)│
│       ▲              │             │              │          │
│       └──────────────┴─────────────┴──────────────┘          │
│                        （计划统合各环节）                       │
│                                                              │
│   【逆向循环：退货/回收价值流】                                 │
│                                                              │
│   Return(退货) ◄── 采购退货 / 制造退货 / 客户退货（三个源头）     │
└────────────────────────────────────────────────────────────┘
```

- **正向循环**：Source → Make → Deliver 构成订单履行的主价值流
- **逆向循环**：Return 处理三个环节的退货（采购退货、制造退货、客户退货）
- **Enable（使能）**：治理、绩效、人力、资产、IT 等支撑流程，纵向贯穿两个循环
- **Plan（计划）**：统合正向循环的需求/供应平衡，是"循环之上的循环"

### 2.2 SCOR 流程分级（与 4A L1-L5 对齐）

| SCOR 层级 | 名称 | 示例 | 对应 4A 层级 |
|-----------|------|------|------------|
| Level 1 | 流程类型 | Plan / Source / Make / Deliver / Return / Enable | L1 价值链 |
| Level 2 | 流程类别 | sM1 采购库存产品 / sM2 采购按订单生产产品 | L2 价值阶段 |
| Level 3 | 流程元素 | sM2.2 评估供应商（含询价/比价） | L3 业务环节 |
| Level 4 | 流程实践 | 供应商准入流程 | L4 流程 |
| Level 5 | 流程活动 | 提交供应商准入申请 | L5 操作 |

> **使用要点**：OTD 类价值链的 L2/L3 节点可直接采用 SCOR Level 1/2/3 编号（如 sM2、D1.1），命名附注编号。

### 2.3 SCOR KPI 体系（五大绩效属性）

价值链设计完成后，MUST 建议为每条价值链挂接 KPI。SCOR 五大绩效属性是标准参照：

| 绩效属性 | 含义 | 典型指标（L1 级） |
|---------|------|------------------|
| **可靠性 Reliability** | 交付结果的正确与完整程度 | 完美订单履行率（POF）、订单履行准确率 |
| **响应性 Responsiveness** | 履行速度 | 订单履行周期（OFC）、询报价响应时长 |
| **敏捷性 Agility** | 应对需求波动的能力 | 供应链上升柔性、供应链适应性 |
| **成本 Cost** | 供应链运营经济性 | 总供应链管理成本、销货成本占比 |
| **资产管理 Asset Management** | 资本利用效率 | 现金周转期（C2C）、供应链固定资产回报率 |

> **落地要求**：蓝图输出的"三架构对齐验证表"之后，建议附**价值链 KPI 挂接表**：每条 BA-L1 价值链 × 至少 2 个 SCOR 属性 × 具体指标及目标值（量化，不接受"提升效率"类模糊表述）。

## 3. APQC PCF（流程分类框架）与 EBPM

### 3.1 APQC PCF

APQC PCF（Process Classification Framework）是跨行业通用流程分类字典，采用五级分层：**类别 Category → 流程组 Process Group → 流程 Process → 活动 Activity → 任务 Task**，与本 skill 的 L1-L5 完全同构。

**跨行业版顶级类别（13 个，PCF v7.x）**：

| # | 类别 | 与价值链的对应 |
|---|------|--------------|
| 1 | 制定愿景与战略 | 使能（规划类） |
| 2 | 开发与管理产品和服务 | IPD 类 |
| 3 | 营销和销售产品与服务 | MTL / LTC 前段 |
| 4 | 交付产品与服务 | OTD / LTC 后段 |
| 5 | 管理客户服务 | CSM / ITR 类 |
| 6 | 开发与管理人力资本 | HR |
| 7 | 管理财务资源与资产 | FIN |
| 8 | 采购、寻源及付款获取 | SCOR Source / P2P |
| 9 | 计划与管理供应链 | SCOR Plan / Make / Deliver |
| 10 | 管理环境、健康与安全（EHS） | 使能（合规类） |
| 11 | 管理知识、改进与变革 | 使能 |
| 12 | 管理风险、合规与补救 | 使能 |
| 13 | 管理外部关系 | 使能 |

**使用要点**：
- L2/L3 节点命名可参照 PCF 编号（如 4.4.1 管理订单、4.4.3 执行仓储与配送），并附注编号
- PCF 的价值在于**完整性校验**：价值链设计完成后，对照 PCF 相关类别检查是否有重大环节遗漏（如设计了 OTD 却遗漏了逆向退货环节）

### 3.2 EBPM（企业业务流程管理方法论）

EBPM 的核心是**端到端流程架构 × 职能流程架构**双维度建模：

- **端到端流程（价值链）**：回答"为客户创造价值的完整路径"——对应本 skill 的**价值线**
- **职能流程（能力）**：回答"组织持续开展的标准工作"——对应本 skill 的**能力线**
- 端到端流程 = 职能流程的逻辑串联（与 N:1:1 中"N 条路径共享原子 BO"的哲学一致）

**流程要素模型（六要素）**：每个 L4 流程应可追溯：输入/输出、角色（岗位）、制度（规则依据）、风控点、承载系统、关联数据。

> **落地要求**：本 skill 的"价值线 + 能力线在 L4 汇聚"设计与 EBPM 完全同构；输出 BA 层次表时，能力线节点的检验可参照 EBPM 职能流程完整性原则——同一能力可支撑多条端到端流程，且能力命名 MUST 用名词（与 ba-standard.md L1-L3 能力线命名规范一致）。

## 4. 离散制造 OTD 实践（Order to Delivery / 从订单到交付）

OTD 是离散制造业（含重工配件、机加工、外贸制造）最核心的端到端价值链之一，覆盖"接单 → 交付"全流程。

### 4.1 OTD 参考骨架（L1-L3）

> **主框架锚定**：SCOR（正向循环 Plan/Source/Make/Deliver 为主干）
> **交叉参照**：APQC PCF 类别 4（交付产品与服务）与类别 9（计划与管理供应链）

| 层级 | 节点（示例，按业务裁剪） |
|------|------------------------|
| **L1** | 从订单到交付（OTD） |
| **L2** | 订单接入与评审 · 订单计划与承诺 · 寻源与采购 · 制造执行 · 质量管理 · 仓储与发运 · 交付与回款 |
| **L3** | 订单接入与评审下：技术图纸评审、产能/工艺评审、报价与交期承诺 |
| | 订单计划与承诺下：主生产计划、排产与外协分配 |
| | 寻源与采购下：外协厂寻源、外协询价与比价、采购下单与跟踪 |
| | 制造执行下：铸造/锻造/焊接/机加工执行（按工艺路线）、外协进度跟踪 |
| | 质量管理下：来料检验（IQC）、过程检验（IPQC）、终检（FQC）、出货检验（OQC） |
| | 仓储与发运下：入库管理、包装、出口单证、发运物流 |
| | 交付与回款下：交付签收、验收异议处理（此段下游接 LTC 开票回款） |

### 4.2 纯外协模式（贸易 + 设计 + 外协）变体提示

无自有工厂的贸易商模式下：
- "制造执行"环节的物理执行方为外协厂，但**业务主权仍在甲方**：外协订单 BO、外协厂评估 BO、质检标准 BO 的 Data Owner 均为贸易商自身系统
- 参照 Mode B（外部系统集成建模）的 E1/E2 规则：外协厂执行能力可对接外部协同平台，本地 MUST 保留统一 BO
- 逆向循环（Return）不可省略：重工配件行业退换货/质量索赔是高频场景，SCOR 逆向循环 MUST 纳入骨架（至少占位）

### 4.3 OTD 常用 KPI（挂接 SCOR 属性）

| SCOR 属性 | OTD 典型指标 |
|-----------|-------------|
| 可靠性 | 准时交付率（OTD Rate）、完美订单率（数量+质量+单证全部正确） |
| 响应性 | 订单履行周期（接单到交付）、报价响应时长 |
| 敏捷性 | 急单承接柔性、外协产能爬坡周期 |
| 成本 | 单件交付成本、外协管理成本占比 |
| 资产管理 | 外协在制品周转、应收账款周转期（DPO/DSO） |

## 6. 多框架锚定工作法（Step 0 / Step 1 执行细则）

1. **识别业务域**：判断输入需求属于哪类业务场景（对照 §5）
2. **主框架锚定**：从主框架的预定义 L1-L3 节点中选取（MUST NOT 自由命名）
3. **交叉校验**：用第二框架做完整性检查（推荐 APQC PCF——它是天然的全覆盖清单）
4. **编号附注**：为 L2/L3 节点附注框架编号（SCOR 编号或 PCF 编号），保证可溯源
5. **KPI 挂接**：为每条 L1 价值链按 SCOR 五大绩效属性建议 ≥2 个量化指标
6. **裁剪**：按 S0-3 最小节点裁剪原则，超范围节点占位不展开
7. **链属边界判定**：按 §7 三问检验执行主链/使能链/支撑链分层，识别使能链与支撑链环节（S0-4），确定多链协同结构

## 7. 价值链链属分层与边界判定（Chain Tier Classification）

> **定位**：任何一条端到端价值链在展开 L2–L4 时，MUST 执行链属边界判定，防止"宽口径单链"把使能链/支撑链环节静默吸收为主链价值阶段。本节为 Step 0 的 S0-4 步骤提供判定规则。

### 7.1 三级链属分类

| 链属 | 定义 | 判定特征 | 参照框架依据 |
|------|------|---------|-------------|
| **主价值链（Main）** | 直接承载客户价值主张的端到端编排链，回答"L1 名称承诺的业务结果" | 客户可直接感知；链名即范围；是**编排者**，通过事件调用使能链 | 华为端到端主流程（LTC/IPD/OTD 等）；SCOR 正向循环主价值流 |
| **使能价值链（Enabling）** | 被主链调用以完成履行的执行能力链，自身也按端到端组织 | 主链"调用"而非"拥有"；有独立的计划-执行-回传闭环；服务多条主链 | SCOR **Enable/使能流程**纵向贯穿思想；华为"主业务流 + 使能流"分层 |
| **支撑价值链（Supporting）** | 企业级通用职能支撑，不直接创造客户价值 | 跨主链复用；治理/合规导向；通常由主链末端事件触发 | APQC PCF 类别 6/7（人力/财务）等支撑类别 |

**关键区分**：使能链是"被调用的执行者"（如供应链执行、工程设计），支撑链是"末端触发的记录者"（如财务应收、合规）。两者都不得划入主链 L2 价值阶段。

### 7.2 边界判定三问（对每条 L4 候选流程逐一执行）

1. **口径检验（名称即范围）**：该流程的业务结果是否落在 L1 价值链名称的**字面范围**内？
   - 例：链名"从订单到交付"→ 开票回款不在字面范围内（属收款/财务链），必须外移
2. **所有权检验（编排 vs 执行）**：主链对该环节是**编排**（发起触发、接收回传）还是**执行**（持有流程主体与 Data Owner）？
   - 执行类环节驻留自己的使能链，主链仅通过跨链接口调用；主链 MUST NOT 把使能环节的流程吸收为自己的价值阶段
3. **框架检验（标准驻留）**：该环节在标准框架中驻留在哪条链？
   - SCOR 中 Plan/Source/Make/Deliver 驻留供应链链内（OTD 主链仅调用）；APQC PCF 中财务结算驻留类别 7（FIN 支撑链）而非类别 4（交付）

**判定优先级**：口径 > 所有权 > 框架。三问结论冲突时按此优先级裁决，并显式记录裁决理由。

### 7.3 灰色地带处理规则

交界流程（如出厂验收在制造质量域但本质是客户验收动作、发运物流在 SCOR Deliver 是履行组成但在华为式分层驻留供应链使能链）MUST：

1. 按判定三问裁决主属链，流程编号用主属链前缀
2. 在蓝图中以"灰色地带记录"显式登记：流程、冲突原因、裁决结论、依据
3. MUST NOT 静默吸收到主链（宽口径陷阱），也不得为图"口径纯粹"而删掉履行主干——正确做法是**多链协同结构**（见 ba-standard.md 多链规范）

### 7.4 常见链属组合模式（按业务场景）

| 业务场景 | 主链 | 典型使能链 | 典型支撑链 |
|---------|------|-----------|-----------|
| 订单履行类（制造/外贸） | 订单到交付（OTD，LTC 合同执行段） | ISC 集成供应链、工程设计（IPD 交付段） | FIN 应收（开票回款） |
| 销售全流程类 | 线索到收款（LTC） | 报价/方案设计、供应链承诺（ATP） | FIN 应收 |
| 产品研发类 | IPD 集成产品开发 | 需求管理链、试制供应链 | FIN 研发核算 |
| 售后服务类 | ITR 问题到解决 | 备件供应链、现场服务调度 | FIN 服务结算 |
| 采购类 | P2P 采购到付款 | 供应商协同、物流 | FIN 应付 |

> 使用要点：本表是**模式参考**而非固定答案——每个企业的链属划分随组织主权与系统边界不同，MUST 按 7.2 三问结合企业实际裁决；跨链共享主数据（客户档案、物料主数据、供应商档案等）不专属任何一条链，在矩阵中以"跨链主数据"身份出现。
